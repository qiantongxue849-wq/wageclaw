# WageClaw 三款小游戏前端与交互优化方案 V2

> 范围：桌面切磋、五子棋、怨气闯关，以及三款游戏的统一入口。  
> 本轮目标：先完成体验方案和关键设计图，不改动现有游戏数值与引擎逻辑。  
> 关键设计原型：`design/games-v2-prototype.html`

## 1. 结论先行

现有三款游戏已经具备完整玩法、动画和奖励闭环，粗糙感并非来自“功能太少”，而是来自四个界面层问题：

1. **入口没有游戏感**：桌宠页用三个普通按钮并列，玩家看不到玩法、耗时、奖励和历史成绩。
2. **三款游戏共用普通弹窗语法**：标题、内容、底部按钮的结构过于工具化，缺少统一游戏壳层，也没有各自的舞台气质。
3. **主状态与次状态抢层级**：格斗的生命/能量/战报分散；五子棋回合与战绩悬空；跑酷把最重要的操作说明放在舞台外。
4. **过程态与结算态没有形成闭环**：重新开始按钮常驻；奖励上限、最佳成绩、下一目标只在文本里出现；退出、暂停、失败后的动作不够清楚。

V2 建议建立一个统一的「解压游戏厅」体验模型：

`游戏大厅 → 玩法准备/快速说明 → 沉浸游戏态 → 结算卡 → 再来一局/返回大厅`

三款游戏共用顶部状态栏、退出/暂停、奖励说明、结算结构和键盘提示；舞台、主色、动效和控制区分别定制。

## 2. 体验目标

| 目标 | 对应设计动作 | 验收信号 |
|---|---|---|
| 3 秒内知道玩什么 | 游戏大厅使用三张大卡，展示玩法标签、单局时长、奖励、个人成绩 | 首次用户无需点入即可区分三款游戏 |
| 1 秒内看懂当前状态 | 顶部统一 HUD；游戏主状态只保留 1 个视觉焦点 | 玩家不依赖长句战报也能判断回合/危险/能量 |
| 键鼠操作都自然 | 键位直接进入按钮视觉；跑酷大操作键固定在舞台内 | 所有核心操作均可点击，也可键盘触发 |
| 失败后愿意再来一局 | 结算突出成绩、收益、距离下一奖励/纪录的差值 | 结算页主按钮始终是明确的“再来一局” |
| 保持 WageClaw 品牌一致 | 保留米白纸张、深墨绿、陶土橙、桌宠真实资产 | 不像三个外部小游戏嵌入主产品 |

## 3. 统一游戏壳层

### 3.1 游戏大厅

把桌宠页当前的三枚按钮升级为一张「解压游戏厅」模块：

- 顶部：今日游戏任务进度、活动爪币剩余额度、总战绩入口。
- 主区：三张玩法卡，分别展示「策略/休闲/反应」、预计单局时长、奖励和历史最佳。
- 卡片主视觉：直接使用当前桌宠形象和纯 CSS 场景，不新增大体积图片。
- 默认主推荐：根据每日任务、未完成成就或最近游玩记录动态推荐；无数据时推荐桌面切磋。
- 点击卡片主体即开局，卡片右上角的“?”打开 3 步玩法说明，不让说明打断老玩家。

### 3.2 游戏内顶部栏

三款游戏统一为：

- 左侧：返回游戏厅、游戏名、玩法标签。
- 中部：当前局最重要的单一状态，如「你的回合」「连击 x3」「速度 1.8x」。
- 右侧：奖励上限提示、音效、暂停/退出。
- 活跃局退出时二次确认，并明确“是否结算当前收益”；静止或已结算状态可直接退出。

### 3.3 通用结算卡

结算层不再只是覆盖一行文案，而是固定展示：

- 结果：胜利 / 失败 / 平局 / 主动撤退。
- 本局：得分、连击、用时或落子数。
- 收益：实际到账爪币；如果达到每日上限，显示“今日额度已满”，避免用户误认为奖励丢失。
- 成长：刷新纪录、成就推进、每日任务推进。
- 动作：主按钮「再来一局」，次按钮「返回游戏厅」，可选「查看战绩」。

## 4. 分游戏优化

### 4.1 桌面切磋：从“按钮面板”升级为“回合战斗台”

**视觉结构**

- 顶部采用对称生命条：左侧玩家、右侧老板，中间显示回合与连击。
- 爆发能量放到技能区上沿，形成“能量 → 可用技能”的直接关系。
- 中央舞台扩大到弹窗的 55% 高度，保留桌宠真实资产；老板怨念体改为统一的办公室纸偶造型，避免两个 emoji 拼接的临时感。
- 战报收为舞台底部单行 ticker，只展示最近一条；详细记录可从“战报”展开。

**操作区**

- 六个技能按「基础攻击 / 爆发技能 / 生存」分组，而不是无差别 3×2 网格。
- 键位使用实体键帽视觉，技能名、效果、消耗三层排版。
- 爆发不足时按钮禁用并显示缺口，例如「还差 8」；不再等点击后才用状态文字反馈。
- 将隐藏的 Q/E 闪身纳入一个可见的「闪身」按钮，键帽显示 `Q / E`。
- 敌方行动期间锁住技能区，并在按钮区上方显示 300ms 的“老板反击中”，避免连点带来的迟滞误解。

**动效优先级**

1. 命中停顿 80–120ms + 轻微位移。
2. 生命条延迟损耗层，先掉即时条，再追上残影条。
3. 暴击、怨气波才震屏；普通攻击只做局部反馈。
4. `prefers-reduced-motion` 下关闭震屏和大位移，保留颜色/数字反馈。

### 4.2 五子棋：从“孤立棋盘”升级为“桌面对弈”

**视觉结构**

- 棋盘占左侧约 68%，右侧为软团对手席，包含回合、战绩、最近一步、重新开始。
- 棋盘四周增加行列坐标，降低大棋盘定位成本，也利于复盘和无障碍播报。
- 回合状态固定在右侧对手席，不再悬浮在棋盘上方挤占纵向空间。
- 最后一手、预落点、胜利五连使用三种不同标记：红点、半透明棋子、金色连线，避免全靠棋子发光。

**交互**

- 玩家落子后立即出现落点标记，AI 思考时锁盘并在软团头像周围显示思考波纹。
- “重新开始”在进行中点击需要确认；结果出现后自动变为主按钮。
- 新增难度入口：`轻松 / 认真`。本轮可以只上线一个难度，但 UI 和数据结构预留；“认真”对应后续两层极大极小 AI。
- 棋盘小于 520px 时不硬压棋子尺寸，切换为横向可滚动棋盘或紧凑 13×13 模式需产品另行决策；桌面主窗口优先保证 15×15 清晰度。

### 4.3 怨气闯关：从“动画区域”升级为“可读的节奏跑酷”

**视觉结构**

- 分数、最佳、速度放到舞台内顶部，避免视线在标题栏和跑道之间跳动。
- 危险区用半透明竖向判定带提示，首次 3 局显示，熟练后可关闭。
- 地面障碍统一陶土红，空中障碍统一钴蓝，同时用箭头与标签提示“跳 / 蹲”，不只依赖颜色。
- 场景做三层视差：远景办公室天际线、便利贴云层、桌面跑道；全部可以纯 CSS 实现。

**操作与节奏**

- `跳跃`、`下蹲`两个大按钮直接悬在舞台底部，键帽与动作绑定；“重新开始”只在结算层出现。
- 第一次开局用两步无惩罚教学：一个地面障碍教跳、一个空中障碍教蹲，之后才计分。
- 增加暂停：窗口失焦自动暂停，恢复时 3-2-1 倒数，防止桌面应用切换窗口导致无故失败。
- 连续正确躲避形成“摸鱼连段”，只改变表现和额外分数，不额外发爪币，避免破坏当前经济上限。
- 撞击后先冻结 250ms，再进入结算；结算强调本局得分、最佳差值和实际奖励。

## 5. 关键状态矩阵

| 游戏 | 准备态 | 进行态 | 系统等待态 | 结算态 |
|---|---|---|---|---|
| 桌面切磋 | 对手与技能预览，开始战斗 | 技能可用、生命/爆发实时更新 | 老板反击中，技能锁定 | 胜负、连击、奖励、再来一局 |
| 五子棋 | 难度、执子说明 | 玩家可落子、预落点 | 软团思考，棋盘锁定 | 胜负平、落子数、奖励 |
| 怨气闯关 | 2 步操作说明 | HUD、障碍、跳蹲 | 暂停/失焦/恢复倒数 | 得分、最佳差值、奖励 |

## 6. 视觉规范

### 6.1 共用基础色

- 纸张背景：`#F5EEDC`
- 强卡片：`#FFF9EC`
- 主墨绿：`#123F37`
- 文本：`#251F1A`
- 次文本：`#746B5F`
- 描边：`rgba(64, 47, 31, .14)`

### 6.2 游戏识别色

- 桌面切磋：陶土橙 `#C96F43` + 危险红 `#B34B40`
- 五子棋：竹青 `#2D6B55` + 木色 `#D8AF6B`
- 怨气闯关：钴蓝 `#4F67B3` + 警示橙 `#E19838`

识别色只用于状态、按钮和舞台氛围；外层壳、字号、圆角和阴影保持统一。

### 6.3 尺寸与可访问性

- 桌面设计基准：主窗口 1440×900；游戏内容安全区不超过 1180×760。
- 可点击目标不小于 44×44；跑酷主操作不小于 152×56。
- 正文最小 12px，关键状态不小于 16px，分数不小于 32px。
- 所有颜色状态必须同时配文字或图形；所有键盘操作有可见按钮。
- `Esc` 先暂停，再次操作才确认退出；不允许直接丢失跑酷当局。

## 7. 实施优先级

### P0：结构和状态反馈（建议先做）

1. 建立 `GameShell`、`GameHUD`、`GameResultCard` 三个共用组件。
2. 桌宠页按钮改为游戏卡片入口。
3. 格斗技能禁用/缺口、敌方回合锁定、Q/E 可见化。
4. 跑酷控制按钮移入舞台，补暂停与失焦恢复倒数。
5. 统一退出确认和奖励上限反馈。

### P1：独立舞台品质

1. 格斗老板纸偶、生命残影条、技能分组。
2. 五子棋右侧对手席、坐标和胜利连线。
3. 跑酷视差背景、判定带、新手两步教学。

### P2：留存与扩展

1. 最近游玩/每日推荐。
2. 五子棋难度与更强 AI。
3. 轻量音效和音量设置。
4. 单局统计与战绩页。

## 8. 工程落地建议

建议保持 `src/composables/games.ts` 的现有工厂结构，V2 主要改表现层：

```text
src/components/games/
├─ GameShell.vue
├─ GameHud.vue
├─ GameResultCard.vue
├─ GameLobby.vue
├─ DuelGame.vue
├─ GomokuGame.vue
└─ RunnerGame.vue
```

- `GameModals.vue` 只保留路由/挂载职责，避免继续扩张。
- 现有 QA 依赖的 `.duel-stage strong`、第三条能量值 `em` 和技能可访问名称要保留，或同步升级 QA。
- 游戏识别色通过 `data-game="duel|gomoku|runner"` 设置 CSS 变量，不复制三套通用样式。
- 先做布局与状态，再做动效；每阶段跑 `npm run check` 和 Electron 实机截图。

## 9. 验收清单

- [ ] 游戏大厅无需点入即可理解三款玩法差异。
- [ ] 三款游戏在 1440×900 和 1024×720 窗口内无关键内容滚动。
- [ ] 格斗能量不足的技能有明确禁用和差额说明。
- [ ] 五子棋能明确区分当前回合、最后一手和胜利五连。
- [ ] 跑酷失焦自动暂停，恢复前有倒数。
- [ ] 所有核心操作既可键盘触发，也有可见点击入口。
- [ ] 结算卡准确显示实际到账、每日上限、纪录和任务推进。
- [ ] 浅色/森林/樱花/水墨/柑橘主题下对比度可用。
- [ ] `prefers-reduced-motion` 下不震屏、不大幅位移。
