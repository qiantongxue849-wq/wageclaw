## 保存错误处理

`desktop-service.apply()` 原先在写入档案后同步气泡、桌宠、标题栏、托盘和播报，任一原生调用异常都会拒绝整个保存 IPC，导致前端回退设置并误报存储空间不足。现在写入失败仍然拒绝，写入后的原生同步分别记录错误、继续同步其余界面，并返回已提交的设置。前端区分空间、权限和失效窗口连接，成功后清除旧提示。

临时档案测试没有复现用户机器上的具体异常；已覆盖上述保存流程缺陷，并验证真实 Windows 保存、文件写入和重新打开结果。后续真实写入失败会记录详细错误，而不会一律声称磁盘空间不足。

## 互动动画流畅度

`petMotion.ts` 改为有限的 `requestAnimationFrame` 播放，仅动作和换装期间重绘，隐藏后取消，结束恢复原形象。`petPosePlayback.ts` 在姿势停留的最后最多 80ms 混合相邻原画，保留高点停顿；这是图像过渡，不是新增手绘帧或骨骼动画。入场、收尾各 120ms。每个动作仅缓存三个已裁切、缩放的姿势；可见且启用动作的当前桌宠提前加载摸摸／松口气图集，全局仍最多缓存三个图集。

独立桌宠的透明鼠标命中检测使用单独的可读画布，动画中最多每 80ms 更新一次，停止时立即刷新。显示画布不再每次重绘都读取像素。仍保留静态动作开关、减少动态偏好、最后一次互动排队、切换角色与形态处理。

原生 Electron 临时档案实测懒猫第 3 种形态：热身后详情页重绘约 28→60 次/秒，独立桌宠约 23→59～60 次/秒，95% 重绘间隔约 46～50ms→17ms。热身后的摸摸动作像素读取约 51→25 次，耗时约 185→56ms；图集裁切约 51～62→13 次。静止后无持续重绘。首轮及偶发长间隔仍受图片、GPU 初始化和系统负载影响；这些数据是重绘调度测量，不代表原画变成 60 个独立姿势帧。证据为 `output/playwright/motion-cadence-before.json`、`motion-cadence-after.json`，脚本 `native-motion-cadence.cjs`。

## 新闻与内容尺寸

TianAPI 热点接口实测可用。手动轮换把热点提前到第三项，右键桌宠／托盘新增“听条新闻”，首次请求会等接口返回后显示；取不到或关闭时给出明确提示。自动播报沿用 25～45 分钟的间隔、安静模式、上班限制和每日配额，在第 1、4、7、10 个日常槽位优先选择热点，保留下班提醒的优先级与重复过滤。重启保留尚未到期的播报时间，避免开发期间反复重启把提醒一直推迟。接口只返回省略号的摘要不再显示。

概览采用共享的图标／标签／数值三列，宽度按最长内容收紧。所有独立气泡取消固定高度与逗号强制分行，由文字自然换行；ResizeObserver 只在内容尺寸改变时请求调整原生小窗，短句缩小，长句展开。只允许气泡和概览窗口调整自己的大小，并限制尺寸、按桌宠位置避开屏幕边缘。主窗口及桌宠窗口大小保持原样。
