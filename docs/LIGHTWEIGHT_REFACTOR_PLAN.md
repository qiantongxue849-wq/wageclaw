# WageClaw「忍了吧」轻量化改造方案

> 后续方向已更新：请优先阅读 [桌宠常驻 V2 方案](DESKTOP_PET_V2_PLAN.md)。本文件保留为上一阶段记录；收入、日历与数据保护规则继续沿用，常驻形态和技术路线以 V2 为准。

> 本文件供后续 AI 直接读取并执行。交付目标是可运行的轻量版，而非仅输出建议或隐藏菜单。执行前请阅读项目中适用的 AGENTS.md，核验代码现状，并保留工作区已有修改。

## 一、改造目标

将当前以桌宠养成、商城、任务和虚拟货币为主的应用，收敛为一个安静的桌面工具。

用户打开后，应在三秒内看到：

1. 今天在公司已经赚了多少钱。
2. 距离今天下班还有多久。
3. 距离下一个节假日还有多久。
4. 距离自己的春节放假还有多久。
5. 距离预计发放年终奖还有多久。

产品原则：**自动呈现回报和盼头，尽量不要求用户操作。**

## 二、执行约束

- 保留 Vue 3、TypeScript、Vite、Electron 技术栈。
- 沿用当前项目，不新建另一套应用。
- 开始前阅读适用的 AGENTS.md，并检查工作区已有改动。
- 不覆盖用户已有修改，不主动更新无关依赖。
- 不删除旧存档，不将虚拟钱包余额转换成真实收入。
- 无须实现账号同步、AI、社区或新的游戏系统。
- 不发布、不打包安装、不推送远程，交付本地可运行代码与验证结果。
- 常规实现细节自行判断；仅在数据可能丢失或确实无法继续时询问用户。

## 三、页面与功能范围

### 1. 首页：唯一主页面

取消当前侧边栏导航。首页顶部只保留应用名称、金额隐藏开关和设置入口。

#### 第一层：今日回报

- 标题：今日已赚。
- 金额：突出显示，保留两位小数。
- 辅助信息：本月已赚、收入估算说明。
- 无“领取”“入账”“兑换”按钮。
- 数字自动更新，避免整块内容反复跳动。

#### 第二层：下班倒计时

- 与今日收入同等重要。
- 上班中显示时、分、秒，以及今日班次进度。
- 上班前显示“还没上班”，今日金额为零。
- 下班后显示“今天收工了”，保留当日收入总结。
- 休息日显示“今天休息”。
- 下班后、休息日不展示下一次上班倒计时。

#### 第三层：三个固定盼头卡片

| 卡片 | 展示内容 |
| --- | --- |
| 下一个节假日 | 假期名称、距离放假天数、假期长度 |
| 我的春节假期 | 距离个人春节放假日期的天数 |
| 年终奖 | 距离预计发放日期的天数；预计金额可选 |

春节和年终奖没有设置时，显示简洁的设置入口，不展示假数据。

发薪日可作为次要信息显示。首版不增加其他首页模块。

### 2. 桌面迷你窗口

将当前桌宠悬浮入口改成简洁的可选迷你窗口：

- 只显示今日已赚和下班状态。
- 点击可打开首页。
- 支持拖动、关闭、可选置顶。
- 金额隐藏状态与首页一致。
- 默认关闭，在设置中开启。
- 不加载宠物动画、成长和互动系统。

继续使用现有 Electron 窗口能力，避免引入新框架。

### 3. 设置

改为一个设置面板，按内容分组，不保留多层标签导航。

**必填，仅首次使用时填写：**

- 用于估算的月薪，建议填写税后月薪。
- 上班时间。
- 下班时间。
- 每周工作日，默认周一至周五。

**选填：**

- 每月发薪日。
- 个人春节假期开始、结束日期。
- 预计年终奖发放日期。
- 预计年终奖金额。
- 指定日期临时上班或休息，用于调休和个人安排。
- 桌面迷你窗口、置顶、金额隐藏。

提供数据导出和带明确确认步骤的数据重置。

首版只支持当天开始、当天结束的班次；跨夜班次需明确提示暂不支持，不能静默算错。午休默认包含在班次估算时间中，并在说明中告知，不增加复杂考勤功能。

## 四、移除与保留清单

### 从轻量版功能和运行逻辑中移除

- 工资领取、虚拟钱包消费、交易账本。
- 爪币、怨气数值及其账本。
- 商城、供销社、背包、使用记录。
- 心愿商品和碎片拆分。
- 每日任务、成就及奖励通知。
- 宠物属性、饥饿衰减、喂食、喂药、进化。
- 小游戏、随机职场事件、黑屏效果。
- 新闻、复杂提示词配置和相关请求。
- 与上述功能对应的快捷键、定时器和窗口通信。

旧存档中的历史数据保留在备份中，不在新首页暴露。

### 保留并简化

- 工资与作息设置。
- 倒计时计算。
- 本地保存。
- 金额隐私。
- 托盘及窗口管理。
- 可用的更新能力，但不能因更新检查失败影响使用。

本地核心功能不要求登录、不依赖网络。此次不建设新的账号系统。

## 五、收入计算规则

### 1. 统一估算口径

收入是根据月薪和工作安排计算的估算值，不代表银行到账。

定义：

- 月计划工作日数：当月按用户排班、假期及日期覆盖规则计算的上班天数。
- 日估算收入：月薪 ÷ 月计划工作日数。
- 当日进度：班次开始到当前时刻的已过时长 ÷ 班次总时长，限制在 0～1。
- 今日已赚：日估算收入 × 当日进度。
- 本月已赚：本月已结束的计划工作日收入＋今日已赚。

规则：

- 非工作日，今日已赚为零。
- 下班后停止增长。
- 月计划工作日数为零时显示零及说明，禁止除零。
- 本月已赚不超过填写的月薪。
- 修改月薪或排班后，按新设置重新估算当月，并用简短说明告知用户。
- 发薪倒计时与收入估算独立，不能将两次发薪日之间的自然时间比例称为“已赚工资”。
- 预计年终奖不计入今日或本月已赚。

### 2. 关闭应用不影响计算

按当前时间和配置直接推导收入。

禁止使用“应用每运行一秒，就往存档增加一笔钱”的方式。

刷新、重启、睡眠唤醒及切换窗口后，金额应一致；多个窗口不能重复累计。

### 3. 金额隐私

隐藏金额时，应同时覆盖：

- 今日收入。
- 本月收入。
- 预计年终奖。
- 迷你窗口、托盘中的金额。

避免通过提示文案或悬停内容泄露隐藏金额。

## 六、日期与倒计时规则

### 1. 工作日优先级

从高到低：

1. 用户对具体日期设置的上班／休息覆盖。
2. 已设置的个人春节假期。
3. 适用地区已确认的年度放假与补班安排。
4. 用户每周工作日设置。

首版面向中国大陆假期安排，不扩展多国家日历。

### 2. 节假日

- 使用按年份维护的假期开始、结束日期和补班日期。
- 不能继续将春节、端午、中秋写成每年固定公历日期。
- 数据应来自可核验的官方年度通知，记录来源和年份。
- 倒数到假期开始，不仅是节日本身的日期。
- 假期期间显示“正在放假”和剩余假期天数。
- 新年度安排未确认时显示“假期安排待公布”，不得复制上一年的日期。
- 年度数据缺失不应导致页面报错；工作日估算退回用户排班并说明缺少调休信息。
- 不为此引入必须长期在线的后台服务。

### 3. 春节放假

使用用户自己的放假日期，允许不同于公共假期安排。

- 未填写：显示“设置你的春节假期”。
- 已填写：按个人开始日期倒数。
- 假期中：显示“春节假期中”。
- 假期结束：提示设置下一次，不自动套用旧日期。

若只填写开始日期，届时显示“春节假期开始了”，不虚构结束日期。

### 4. 年终奖

- 日期和金额均由用户填写。
- 明确显示“预计发放”。
- 到达日期后显示“预计今天发放”。
- 日期过去后显示“预计日期已到”，允许修改日期或手动标记已收到。
- 不自动认定奖金到账。
- 不自动按年重复旧日期。

### 5. 通用日期细节

- 长期倒计时默认显示自然日，避免界面同时堆叠多个口径。
- 使用本地日历日期计算天数，不简单将毫秒差除以 24 小时。
- 正确处理跨月、跨年和闰年。
- 发薪日允许 1～31 日；当月没有该日期时，使用当月最后一天。
- 发薪日当天全天显示“今天发薪”，不要在凌晨后跳到下个月。

## 七、视觉与交互要求

整体方向：安静、清楚、能在工作间隙一眼看完。

- 一个首页，不使用管理后台式侧栏。
- 收入和下班倒计时突出，其余卡片降低视觉权重。
- 默认采用低刺激、清晰易读的配色。
- 首版提供浅色、深色即可，不新增大量主题。
- 数字使用等宽数字样式，避免刷新时位移。
- 不用闪烁、金币喷射、满屏庆祝、强烈红色警报。
- 不设置签到、连续使用天数和未完成红点。
- 不增加声音或周期性弹窗。
- 文案温和简短，不反复强化怨气，不鼓励延长加班。
- 常见桌面窗口尺寸下，核心内容无需滚动。
- 较窄窗口自然改为单列，不能遮挡设置入口和金额。

## 八、代码改造建议

开始时核验文件现状。当前可优先检查：

- `src/App.vue`：应用外壳和导航。
- `src/components/ConverterScreen.vue`：当前首页。
- `src/composables/useWageClaw.ts`：收入、状态及大量养成逻辑。
- `src/utils/countdown.ts`：倒计时。
- `src/utils/salary.ts`：发薪日期。
- `src/state/tuning.ts`：现有固定节日配置。
- `src/state/defaults.ts`、`sanitize.ts`、`persistence.ts`：存档。
- `src/components/SettingsScreen.vue`：设置。
- `electron/app-shell.cjs`、`app-windows.cjs`、`app-tray.cjs`、`app-ipc.cjs`：桌面运行逻辑。

建议将新核心分为：

- 收入估算。
- 工作日历。
- 倒计时。
- 轻量版状态与设置。
- 首页、设置面板、迷你窗口。

不要继续将新逻辑追加进庞大的旧状态模块。

### 运行与资源

- 可见窗口最多每秒刷新一次时间。
- 长期日期结果仅在日期或配置改变时重新计算。
- 隐藏窗口停止不必要的动画和刷新，恢复显示时重新计算。
- 只在配置和用户操作改变时保存，禁止每秒保存收入。
- 移除未使用的宠物、游戏和商城资源导入。
- 清理对应样式，避免新页面继续加载全部历史样式。
- 不同时维护“完整版／轻量版”两个运行分支。
- 不承诺未经测量的内存或包体降幅。

## 九、数据兼容

使用独立版本的新存档结构，保存配置和必要的用户状态，不保存实时累计金额。

迁移要求：

1. 原样保留旧存档或生成备份。
2. 迁移有效的月薪、上下班时间、发薪日及隐私偏好。
3. 缺失的新配置使用合理默认值或显示待设置。
4. 不迁移虚拟余额为收入。
5. 已有多账号数据时，避免混合不同用户存档。
6. 迁移可重复执行，不覆盖用户后来修改的新设置。
7. 损坏存档不能导致白屏；保留原始数据，并提供恢复默认设置的路径。

## 十一、验收标准

### 功能

- 首次使用不要求选择心愿、宠物或注册账号。
- 首页清楚呈现今日收入、下班状态及三个盼头卡片。
- 收入无需领取，关闭后重新打开不丢失估算进度。
- 休息日不继续计算今日收入。
- 下班后不继续增长，不立即展示上班倒计时。
- 春节使用个人放假安排。
- 年终奖未设置时无假数据，日期过去后不自动到账。
- 隐私开关覆盖首页和迷你窗口。
- 轻量版中没有商城、喂养、任务、成就和游戏入口。

### 计算测试

至少覆盖：

- 上班前、上班中、下班时刻、下班后。
- 普通周末、补班日、假期、个人日期覆盖。
- 月末、年末、闰年、月底发薪。
- 发薪日当天。
- 假期开始、假期期间、假期结束。
- 次年节日数据缺失。
- 年终奖日期当天与过期。
- 重启和睡眠唤醒后的计算一致性。
- 旧存档迁移、重复迁移和损坏数据回退。

不为纯文案、装饰样式或显而易见的实现细节堆砌测试。

### 工程

- 核心功能离线可用。
- 没有遗留养成定时器和无用网络请求。
- 控制台无新增错误。
- 所有适用检查通过。
- 用户已有改动与旧数据得到保留。

## 十二、最终交付说明

执行完成后提供：

1. 实现了哪些变化。
2. 首页和迷你窗口截图。
3. 收入与假期的计算口径。
4. 旧数据迁移、保留方式。
5. 检查与测试结果。
6. 尚未完成或未能验证的内容。

**最终判断标准：用户打开应用就获得回报感和休息的盼头，无须再完成一轮应用里的任务。**
