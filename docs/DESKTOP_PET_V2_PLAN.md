# WageClaw V2：桌宠常驻、轻量播报、按需打开面板

> 当前有效的下一阶段优化方案。与 `LIGHTWEIGHT_REFACTOR_PLAN.md` 冲突时，以本方案为准。
> 本次只制定方案，不执行代码改造。后续 AI 收到明确实施指令后，再按本文件执行。
> 本方案保留已经完成的收入、日期与数据保护规则，调整产品入口、桌面形态和后续技术路线。

## 1. 产品定位

**一只陪你等下班的桌宠，偶尔告诉你：今天的付出有回报，下一次休息也在靠近。**

日常留在用户桌面上的主体是有形象、有轻微动作的桌宠。当前收入和倒计时卡片作为按需打开的详情面板。

产品由三部分组成：

1. **桌宠**：常驻入口，轻微待机、拖动、点击互动。
2. **播报气泡**：偶尔显示一句与当前收入或日期有关的话，数秒后消失。
3. **详情面板**：用户主动打开时展示完整收入、下班、假期和年终奖卡片及设置。

保留陪伴感，不恢复需要用户照料的养成负担。

### 已确认的面板入口

用户已明确确认：直接打开面板，无需登录。双击桌宠打开本地详情面板，不新增账号系统、服务端或登录门槛。

即使将来增加云同步，桌宠、收入计算与离线播报仍应可独立使用。

## 3. 用户的完整使用路径

### 首次启动

1. 桌宠出现在桌面角落，展示一次欢迎气泡。
2. 打开首次配置面板，只填写月薪、上下班时间和每周工作日。
3. 春节和年终奖日期可跳过，之后随时补充。
4. 保存后关闭配置面板，留下桌宠和托盘。
5. 一次性提示：“点我看一句，双击看全部；拖动可换位置。”

如果用户暂不设置，桌宠仍可安静存在；不显示虚构金额，不反复弹出配置面板。

### 已配置用户启动

- 恢复上次桌宠形象、位置、大小和显示偏好。
- 不自动打开详情面板，不弹出登录或更新弹窗。
- 等待下一个合适的播报时机，启动即刻不连发旧提醒。
- 开机自启为可选项，默认关闭；用户开启后也只出现桌宠和托盘。

### 想查看信息时

- 单击桌宠：看一条简短播报。
- 双击桌宠：打开现有卡片详情面板。
- 关闭面板：桌宠继续运行，播报不受影响。
- 用户可以从桌宠右键菜单或托盘打开面板，不必记住隐藏手势。

## 4. 桌宠形象与动作

### 复用旧版资源

默认优先恢复旧版卡皮巴拉形象；如果旧档中有有效皮肤偏好，可沿用对应形象。第一阶段只恢复默认形象及满足旧偏好所需的资源，其余皮肤作为后续可选项。

复用范围：

- 桌宠图片、精灵图与少量现成动作。
- 透明背景、基础拖动、位置恢复的可用实现思路。
- 已验证的点击与拖动区分方法。

不直接恢复整套旧运行时。旧运行时绑定爪币、衰减、成长、随机事件和提醒，不能整体接回。

### 最小动作集

| 状态 | 动作建议 |
| --- | --- |
| 待机 | 静止为主，间歇眨眼或轻微呼吸 |
| 单击 | 一次短促回应，再显示气泡 |
| 播报 | 轻微抬头、挥手或现有短动作 |
| 下班后／休息日 | 更安静的坐着或小睡姿态 |
| 拖动 | 跟随位置，不触发其他动作 |

限制：不自动满屏移动、不弹跳风暴、不黑屏、不长时间循环高帧率动画。不出现饥饿、掉血、未喂养等负面状态。

建议桌宠视觉主体约 100～140 个逻辑像素，设置提供小／中／大三档。透明窗口尽量贴合实际交互区域，不能用大面积透明矩形挡住其他应用。

## 5. 点击与拖动协议

默认交互：

| 操作 | 行为 |
| --- | --- |
| 单击 | 显示一条当前最有用的简报 |
| 双击 | 打开或聚焦详情面板 |
| 拖动 | 移动桌宠，松开后保存位置 |
| 右键 | 打开菜单 |
| 点击气泡中的“查看” | 打开详情面板 |

- 不将三击／多击作为必学入口；用户的“点击几次”用双击即可满足。
- 单击动作须等待双击识别窗口，避免双击时先弹单击气泡。
- 优先尊重系统双击习惯；无法获取系统阈值时使用可测试的统一阈值。
- 指针移动超过约 6 个逻辑像素进入拖动，取消本次单击／双击。
- 一次手势只执行一个动作；快速连击不同时打开多个窗口。
- 右键菜单至少包含：查看详情、立即播报、暂停一小时、今天安静、设置、隐藏桌宠、退出。
- 隐藏桌宠后仍可从托盘恢复。

## 6. 播报内容设计

默认采用**桌宠旁的文字气泡**，不发出声音，不使用系统通知堆叠。语音播报不进入第一阶段。

每次只讲一个重点，最多两行，显示约 6～8 秒。用户点击其他区域或主动关闭可提前消失。鼠标停在气泡上时可暂停消失计时，避免来不及阅读。

示例数字仅说明文案，实际值必须在展示时计算：

| 类型 | 示例 |
| --- | --- |
| 今日收入 | “今天已经攒了 ¥328.60，辛苦没有白费。” |
| 下班 | “还有 42 分钟，今天就可以收工了。” |
| 公共假期 | “再过 10 天就是中秋假期，能休息 3 天。” |
| 个人春节 | “离你的春节假期还有 28 天，回家的日子近了。” |
| 年终奖 | “离预计发年终奖还有 16 天，留个盼头。” |
| 下班时刻 | “今天辛苦了，接下来的时间留给自己。” |
| 休息日主动点击 | “今天休息。下一次假期也在路上。” |

规则：

- “攒了”采用已实现的工资估算值，不新增可领取钱包；设置和详情面板明确说明“估算，不代表到账或实际储蓄”。
- 年终奖始终带“预计”，到期不能自动说已到账。
- 未设置的春节或年终奖不参与自动播报，不随机催用户补资料。
- 假期未确认时，不编造日期或假期长度。
- 上班前不称“今天已经赚到”；休息日不按工作日增长。
- 下班后不提醒明天几点上班，也不继续播放工作中的倒计时。
- 轮换话题，尽量不连续两次讲同一件事；候选不足时减少播报。
- 同一金额／同一天数未发生有意义变化时，不反复播相同内容。
- 普通数字无需逐秒在气泡里刷新；以气泡出现时的计算结果为准。

### 隐私

隐藏金额时，气泡、详情面板、托盘和任何辅助说明都必须遵守：

- 将金额替换为不含数值的表达，例如“今天的收入还在慢慢积累”。
- 不通过每小时收入、日薪、比例反推出薪资。
- 当前气泡显示期间切换隐私开关，须立即重新脱敏或关闭，不能等下次播报才生效。

## 7. 不定期播报机制

使用本地规则和文案模板即可，不调用 LLM，不引入云端定时任务。

### 默认策略（可调参数，先按此验证）

- 普通自动播报：在实际工作时段内，随机间隔 60～120 分钟。
- 每工作日普通自动播报最多 3 次。
- 关键节点：距下班 30 分钟，以及下班时刻，各最多 1 次。
- 全部自动播报每日合计最多 5 次，相邻自动播报至少间隔 20 分钟。
- 在关键节点前后 15 分钟不安排普通随机播报。
- 单击产生的主动播报不消耗自动次数，但做约 2 秒防抖，不允许连续堆叠。
- 设置只需暴露自动播报开关、暂停一小时、今天安静，不暴露所有调参细节。

这些是默认产品策略，不是操作系统能力承诺。验证后可根据真实打扰感调整。

### 触发与优先级

主动点击 > 到点下班 > 下班前提醒 > 普通轮换。

气泡同一时间最多一个，高优先级可以替换低优先级，不把旧播报排成待播放队列。普通播报受限时直接跳过并重新安排。

春节、公共假期和年终奖作为普通轮换话题进入，不额外叠加三套独立定时器。

### 暂停与过期

以下状态禁止自动播报：

- 锁屏、系统睡眠。
- 用户启用“今天安静”或暂停。
- 桌宠已隐藏。
- 实际休息日，或不在工作时段；到点下班提醒为唯一允许的工作结束边界提醒。
- 拖动桌宠、打开设置时，暂缓自动气泡。

不要求读取用户屏幕内容、应用内容或麦克风来判断场景。

全屏／系统勿扰检测作为平台能力单独验证：可可靠获取时暂停；无法可靠获取时不声称支持，保留清楚的手动安静入口。

睡眠唤醒、重启或时钟改变后：

1. 重新读取当前时间、工作状态和暂停期限。
2. 丢弃过期随机播报，不集中补播。
3. 下班提醒超过目标时刻 2 分钟就失效，不在深夜补发。
4. 校验当天已触发记录，避免重启绕过次数上限。
5. “今天安静”在下一个本地日自然失效；跨时区按当前本地日期重算。

## 8. 详情面板的调整

保留当前卡片设计，不重做另一套后台。

面板继续包含：今日已赚、本月已赚、下班状态、公共假期、春节假期、年终奖与设置。

新增少量设置：

- 桌宠显示、大小、置顶。
- 皮肤选择（只列出实际恢复并验证的皮肤）。
- 自动播报开关和临时安静状态。
- 开机自启，默认关闭。

用桌宠替换数字迷你窗口，不同时维护两种常驻形态。

面板关闭时销毁其窗口和前端实例；需要再次查看时重新创建，恢复上次窗口尺寸和必要配置。首次打开与再次打开均须从当前快照计算，不先展示过时数据。

浏览器预览只模拟桌宠／气泡和面板内容，不能将网页悬浮组件视为跨应用桌宠的验证结果。

## 9. 架构调整：面板不能是后台服务

当前代码里，主面板负责保存桌面开关并驱动迷你窗口。若直接销毁面板，桌宠偏好和控制链路会中断；这是本次必须调整的地方。

目标组成：

- **领域计算**：收入、工作日历、事件状态，尽量保持纯函数。
- **桌面运行服务**：持有设置、时间安排、播报去重、窗口生命周期和系统事件。
- **桌宠视图**：只渲染形象、气泡和交互结果。
- **详情面板**：读取快照，提交配置，不担任常驻任务执行者。
- **平台适配层**：窗口、托盘、置顶、拖动、存储、系统事件、自启动。

平台接口建议覆盖：`loadSettings`、`saveSettings`、`getSnapshot`、`subscribeSnapshot`、`openPanel`、`showPet`、`setPetPosition`、`setQuietMode`。

第一阶段可让 Electron 主进程运行编译后的共享计算模块，保持一个计算来源。不要在桌宠、面板和主进程各复制一套薪资逻辑。

持久化设置由桌面运行服务串行处理，写临时文件后替换正式文件，避免多个窗口同时保存相互覆盖。浏览器预览通过独立适配器使用 localStorage。

### 新增状态

建议采用嵌套结构，升级存档版本并提供迁移：

- `pet`：皮肤、尺寸、位置、显示、置顶。
- `broadcast`：开启状态、暂停截止、今天安静日期。
- `delivery`：本地日期、当天自动次数、已触发事件 ID、上次播报时间／话题。
- `preferences`：自启动等平台偏好。

收入本身仍是计算结果，不逐秒保存。状态只在配置变更、拖动结束、播报完成或暂停变化时持久化。

### 旧数据迁移

- 保留本轮 `wageclaw-lite-v1:*` 及更早 `wageclaw-state-v3*` 原始存档。
- 同一档案隔离原则不变，不扫描并合并其他账号。
- 桌面服务切换到文件存储时，原渲染环境做一次受控迁移，将本地档案交给服务端校验落盘；迁移失败不能清空原值。
- 迁移标记必须在新存档写入成功后记录，重复执行不得覆盖新配置。
- 若更换运行时，不假定新 WebView 能自动读取 Electron 的 localStorage。需要旧版本导出、新版本导入或明确的受控迁移通道。
- 运行时迁移阶段必须补齐备份导入与校验，不能依赖手动复制浏览器存储目录。

## 11. 技术路线建议

### 结论

**先用现有 Electron 完成桌宠产品闭环；同时把计算和平台接口拆开。之后用 Tauri 做桌面能力与资源占用验证，通过后再决定迁移。**

不将“前端 108 KB”当作“桌面程序很轻”的证据。桌面轻量需要看全部进程的内存、CPU、唤醒频率、安装包和启动速度。

### 对比

| 路线 | 复用情况 | 本项目适用判断 |
| --- | --- | --- |
| 精简 Electron | 最大程度复用当前 Vue 和现有桌面经验 | 第一阶段最快验证产品；运行时分发负担仍在 |
| Tauri 2 + Vue | 保留主要面板与前端视图，重写平台桥接及部分后台逻辑 | 优先做后续原型；能减少捆绑 WebView 的需求，实际驻留资源需测量 |
| 平台原生桌宠＋按需 Web 面板 | 保留卡片设计，桌宠交互和系统功能按平台实现 | 若只做单平台或跨平台 WebView 方案达不到资源目标，再评估；双平台维护成本更高 |

事实依据：

- Electron 将 Chromium、V8、Node.js 随应用分发，见 [Why Electron](https://www.electronjs.org/docs/latest/why-electron)。
- Tauri 使用系统 WebView，实际 WebView 版本取决于设备，见 [Webview Versions](https://v2.tauri.app/reference/webview-versions/) 和 [Process Model](https://v2.tauri.app/concept/process-model/)。
- Tauri 窗口 API 提供拖动、可聚焦与忽略鼠标事件等接口，但平台差异需验证，见 [Window API](https://v2.tauri.app/zh-cn/reference/javascript/api/namespacewindow/)。
- Tauri 当前配置文档说明，macOS 透明背景相关选项涉及私有 API，可能影响 Mac App Store 分发。若将来计划上架，应把这点列入技术选型条件，见 [Configuration](https://v2.tauri.app/reference/config/)。

以上不代表已经测得 Tauri 更省内存，也不预先承诺安装包或内存的固定数值。

### Tauri 原型必须先通过的场景

1. Windows 与 macOS 的透明无边框窗口表现。
2. 桌宠区域可点，周围透明区不阻挡其他软件。
3. 单击、双击、拖动及右键菜单不冲突。
4. 普通窗口置顶可用，自动气泡不抢输入焦点。
5. 气泡靠近屏幕边缘自动换方向，多显示器和缩放变化不出界。
6. 锁屏／休眠暂停、恢复后不集中补播。
7. 详情面板按需创建和销毁，桌宠继续运行。
8. 从现有 Electron 档案安全迁移。
9. 同样皮肤、帧率、窗口数和播报脚本下测量完整进程树资源。

第一阶段无需为此建立第二套正式发行分支。原型通过后再迁移，发布时只维护一个正式桌面运行时。

## 12. 轻量化实施策略

- 只加载当前桌宠皮肤和当前动作需要的图片。
- 待机以静止为主，每隔一段时间播放短动作；原型先以约 6～10 FPS 的短动画验证观感。
- 不能用 60 FPS JS 循环持续更新桌宠位置或倒计时。
- 播报调度使用“下一次事件”的单次定时器，睡眠／配置改变时重排。
- 面板打开时才逐秒刷新收入与下班数字，关闭后停止相应渲染。
- 不每秒落盘；位置在拖动结束时保存。
- 气泡显示时才创建内容，隐藏后释放。无气泡时不保留会遮挡桌面的透明大框。
- 桌宠和气泡位置统一计算，气泡出现／消失不能导致桌宠跳动。
- 自动播报不激活面板，不打断用户在其他软件中的键盘输入。
- 不请求全局键盘监听、截图或辅助功能权限来实现简单点击互动。

## 13. 性能验证与决策标准

在同一设备、相同皮肤、尺寸、帧率和脚本下比较：

| 场景 | 测量内容 |
| --- | --- |
| 仅桌宠静置 10 分钟 | 全进程内存、CPU、定时唤醒 |
| 间歇待机动画 10 分钟 | CPU 平均值与峰值、掉帧 |
| 展示与关闭气泡 20 次 | 内存是否持续增长、输入焦点是否被抢 |
| 打开并关闭面板 20 次 | 窗口／渲染进程是否释放、是否重复计时 |
| 锁屏与唤醒 3 次 | 恢复后金额、播报去重与时钟正确性 |
| 冷启动 5 次 | 桌宠可交互时间、完整安装体积 |

Tauri 迁移的建议门槛：核心能力全部通过，且在目标设备上资源指标有明确改善。例如完整进程树稳定内存降低约 30%，或静置 CPU／唤醒明显改善，同时不牺牲点击穿透、稳定性和启动体验。这是决策参考，不是预先承诺或必须凑出的结果。

没有 Windows 测试环境时，明确写“Windows 未验证”，不得从 macOS 测试推断跨平台通过。

## 14. 分阶段执行

### 阶段 A：恢复桌宠入口

- 选择性恢复一个旧形象和必要动作。
- 替换当前数字迷你窗口。
- 实现透明窗口、拖动、单击、双击和右键入口。
- 已配置用户启动不打开面板。
- 保留现有卡片与设置，无养成入口。

验收：桌面上看到桌宠；单击有反馈，双击打开卡片，拖动不误触。

### 阶段 B：加入轻量播报

- 实现候选内容、随机间隔、下班节点、优先级、每日上限和去重。
- 实现安静模式、锁屏／休眠暂停、唤醒后重排。
- 验证当前气泡的隐私切换和屏幕边缘定位。

验收：真实工作状态下能自然播报，休息或暂停时安静，不积压、不抢焦点。

### 阶段 C：独立运行与资源收敛

- 将设置与调度移出面板，建立独立桌面运行服务。
- 完成文件存储及现有 localStorage 无损迁移。
- 面板改为按需创建与销毁。
- 完成动画、定时器、窗口和资源测量。

阶段 A/B 可以渐进实现，但阶段 C 完成前不宣称“关闭面板即可释放主界面资源”。

### 阶段 D：替代运行时原型

- 使用同一套资源与交互规则做 Tauri 原型。
- 验证透明、穿透、输入焦点、多屏和档案迁移。
- 提供 Electron／Tauri 同场景对比记录。
- 根据数据决定迁移；若没有收益或体验不稳定，先保留精简 Electron。

用户当前仅要求新方案。本阶段不自动触发技术迁移、发布、安装或远程推送。

## 15. 验收清单

### 产品

- 常驻主体是旧版可识别的桌宠形象。
- 无喂养、任务、爪币、商城或成长压力。
- 双击与右键均可打开现有详情面板。
- 关闭面板后桌宠和调度继续运行。
- 自动播报覆盖收入、下班、公共假期、个人春节及预计年终奖，但只使用有效配置。
- 自动气泡默认静音，不抢焦点，不叠加，不在休息时催工作。

### 计算与数据

- 沿用当前通过验证的收入和日历规则。
- 气泡和面板采用同一来源，金额与日期一致。
- 日上限与关键提醒跨重启去重。
- 休眠后不补播陈旧提醒。
- 隐私切换对已出现的气泡立即生效。
- 原始旧存档可恢复，跨运行时迁移有明确通道。

### 桌面与性能

- 透明区域不挡住其他应用的正常点击。
- 拖动、双击、右键没有重复触发。
- 多显示器断开后桌宠可回到可见区域。
- 气泡不超出工作区，不因打开气泡移动桌宠。
- 面板关闭后释放资源，反复打开不增加后台调度实例。
- 提供实测性能记录，区分前端资源、安装体积和进程内存。
